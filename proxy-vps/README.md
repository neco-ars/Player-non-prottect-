# Свой прокси на сервере (для Звука в веб-версии)

Звук отклоняет запросы с серверов Cloudflare (ответы 400/418/500), поэтому через прокси из папки
[`proxy/`](../proxy) он в веб-версии не работает. Этот прокси делает то же самое, но на **твоём сервере** —
например, в России, откуда Звук запросы принимает. Если поставить его, Звук снова появится в веб-версии
(в приложениях для Android и Windows Звук работает и без него).

- Только Python 3 из стандартной поставки — ничего не нужно устанавливать вручную.
- HTTPS с бесплатным сертификатом (Caddy). Домен не нужен: адрес вида `1-2-3-4.sslip.io` получается из IP.
- Пересылает только запросы к Звуку, SoundCloud, Audiomack, Genius и Deezer (данные для рекомендаций) и только с адреса твоего сайта.
- Не хранит токены и не пишет адреса запросов в журнал.

## 1. Арендовать сервер

Любой недорогой VPS **в России**: 1 ядро, 512 МБ–1 ГБ памяти, система **Ubuntu 24.04** (или 22.04 / Debian 12).
Обычно это 150–300 ₽ в месяц. После создания хостинг пришлёт **IP-адрес** и **пароль root**.

Если в панели хостинга есть файрвол — открой входящие порты **80** и **443** (TCP).

## 2. Поставить прокси (одна команда)

Подключись к серверу. На Windows: открой «Терминал» или PowerShell и введи (вместо `1.2.3.4` — IP сервера):

```bash
ssh root@1.2.3.4
```

Введи пароль (при вводе он не отображается — это нормально). Затем вставь и выполни:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/neco-ars/Player-non-prottect-/main/proxy-vps/install.sh)
```

Через 1–3 минуты скрипт напишет:

```
✅ Прокси работает: https://1-2-3-4.sslip.io
```

Скопируй этот адрес.

## 3. Подключить к сайту

1. В репозитории GitHub: **Settings → Secrets and variables → Actions → Variables** → переменная
   **`PROXY_URL`** → **Edit** → вставь адрес из шага 2 → **Update variable**.
2. Перезапусти сборку: **Actions** → верхний запуск → **Re-run all jobs** (или выпусти новую версию).

Через 5–10 минут сайт обновится, и Звук появится в веб-версии. Прокси на Cloudflare после этого больше не нужен.

## Полезное

- Проверить, что прокси жив: открыть в браузере `https://1-2-3-4.sslip.io` — ответ `Bad url` значит «работает».
- Журнал: `journalctl -u music-proxy -f`
- Перезапуск: `systemctl restart music-proxy`
- Обновить прокси до новой версии: снова выполнить команду из шага 2.
- Другой адрес сайта: `ALLOWED_ORIGIN=https://другой.github.io bash <(curl -fsSL …/install.sh)`
- Свой домен: `DOMAIN=proxy.example.ru bash <(curl -fsSL …/install.sh)` (у домена должна быть A-запись на IP сервера).
